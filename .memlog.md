## 2. Architecture Decision Records (ADRs)

| ADR ID | Title | Decision | Context | Status |
|---|---|---|---|---|
| **ADR-001** | Rust Workspace crate boundaries | 4 separate Cargo crates: `crates/domain`, `crates/application`, `crates/infrastructure`, `crates/api`; `domain` has zero external IO dependencies; `api` depends on all inner crates | DDD + Clean Architecture enforcement; compile-time isolation | ✅ Logged |
| **ADR-002** | PostgreSQL schema separation over multiple databases | Single PostgreSQL instance with 4 dedicated schemas (`auth`, `catalog`, `sales`, `inventory`); schema isolation via `SET search_path`; no separate database instances for MVP | Cost/efficiency vs. isolation trade-off; simplifies cross-context transactions; future read-replica path | ✅ Logged |
| **ADR-003** | Axum for API layer | Axum 0.7 as HTTP framework; Tokio 1.38 as async runtime; `Extension<State>` pattern for dependency injection; `tracing-subscriber` for observability | Rust async web ecosystem evaluation: Axum chosen for minimalism + router composability; Actix-web considered but steeper learning curve | ✅ Logged |
| **ADR-004** | Argon2 + JWT authentication | Argon2id for password hashing (memory=64MiB, time=3, parallelism=2); JWT access tokens 15 min TTL, refresh tokens 7 day TTL with rotation; HMAC-SHA256 signing | Security requirement: resistant to GPU cracking; stateless auth scale; refresh token rotation via `jti` claim | ✅ Logged |
| **ADR-005** | SQLx parameterized queries only | All SQL constructed via SQLx `query!`, `query_as!`, `query!` with `$1`, `$2` placeholders; zero raw string concatenation in application code | SQL injection prevention; compile-time query validation via `sqlx::query!` macro | ✅ Logged |
| **ADR-006** | EUR-fixed currency for MVP | All monetary amounts stored as `i64` cents in `Money` value object; `currency: CurrencyEur` enum; no conversion logic | Time-to-market constraint; Phase 2 multi-currency out of scope; simplifies business logic and testing | ✅ Logged |
| **ADR-007** | Makefile-driven DevOps | Root `Makefile` with targets: `make dev`, `make test`, `make db-up`, `make migrate-up`, `make init-db`; `docker-compose.yml` for PostgreSQL + API orchestration | Developer experience consistency; single-command onboarding; CI/CD parity | ✅ Logged |
